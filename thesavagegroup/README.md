# The Savage Group — website

Source for **www.thesavagegroup.org**. It's a static site generated by a small Node script, with no runtime or npm dependencies.

```
thesavagegroup/
├── content/site.mjs     ← ALL copy, links, image references, projects
├── assets/source/       ← original photographs (replace these)
├── assets/img/          ← generated responsive images (do not edit by hand)
├── assets/brand/DISTRIK.svg  ← supplied DISTRIK logo (replace to update every instance)
├── src/                 ← templates (layout, components, pages), CSS, JS
├── tools/images.py      ← makes responsive image sizes
├── build.mjs            ← renders every page into dist/
└── serve.mjs            ← local preview server
```

Routes: `/`, `/corporate-wellness/`, `/distrik/`, `/our-story/`, `/projects/`, `/contact/`, plus reserved
(noindex, unlinked) holding pages at `/linkedin/sydney/`, `/linkedin/melbourne/` and `/linkedin/singapore/`.

> **Note on location.** This folder currently lives inside the DISTRIK repository (`distrikath.com`) on the
> `savage-group-site` branch, so it doesn't touch the live DISTRIK site. Before launch, move the
> `thesavagegroup/` folder into its own repository (see section 5).

---

## 1. Running the website

Requires Node 18 or newer.

```bash
cd thesavagegroup
npm run dev        # builds, serves http://localhost:4321 and rebuilds on every save
# or
npm run build      # writes the finished site to dist/
npm run preview    # serves dist/ without watching
```

`dist/` is the complete website. It's plain HTML, CSS, JS and images, so any static host can serve it.

## 2. Replacing photographs

1. Put the new photo in `assets/source/` (JPG, PNG or WebP, ideally 2400px or more on the long edge).
   To replace an existing photo, reuse its file name (for example `distrik-lounge.jpg`).
2. Run `npm run images` (needs Python 3 with Pillow: `pip install Pillow`). This creates the 480–2000px
   WebP sizes and updates `assets/img/manifest.json`, which supplies image dimensions so the layout doesn't shift.
3. In `content/site.mjs` → `images`, add or update the entry:
   - `src`: the file name without extension
   - `alt`: describe what's in the photo
   - `pos` / `posMobile`: the crop focus (CSS `object-position`, such as `'70% 30%'`). Use
     `posMobile` to keep faces in frame on phones.
   - `caption`: optional. Only state a location when the photo was actually taken there.
   - `source`: where the photo came from and who approved it.
4. To fill a **placeholder** (stone panels marked "Photography to come"), replace the entry's
   `placeholder: true` / `brief` with a real `src` and `alt`. The page using it updates automatically.

## 3. Updating copy and links

All words, links and settings are in **`content/site.mjs`**. Each page has its own block under `pages`.

- **DISTRIK details** (`distrik`): email, Instagram, Fresha booking link and address.
  `prices` holds the session prices published on distrikath.com; `hours` and `promotions` are
  deliberately empty and hidden. Add them only once confirmed
  (examples are in the comments) and they'll appear on the DISTRIK page.
- **Projects** (`projects`): an entry is published only when both `verified: true` and `public: true`.
  Drafts can stay in the file with `public: false`.
- **Legal entity details** (`site.legal`): empty until supplied. Anything added appears in the footer.
- **Preview mode** (`site.preview`): while `true`, the site shows review notes (dashed boxes),
  placeholder labels and a "Preview build" strip, and every page is `noindex` with a blocking `robots.txt`.
  Set it to `false` only for launch.

Review notes currently on the site:
- Our Story: founder to confirm details. The copy avoids dates, names and claims on purpose.
- Corporate Wellness / Projects: LinkedIn program detail, imagery and outcomes only once approved.
  No LinkedIn logo, testimonial or statistics are used.
- DISTRIK: name the IV and blood-testing clinical partner only once they approve the wording, and
  confirm opening hours and prices.

### Design system

**Grid.** Every page sits on a 4-column grid (2 columns on phones), and every section uses the same
column slots:

| Column | Slot | What goes there |
|---|---|---|
| 1 | Label | Section number and label, e.g. `(02) Corporate Wellness` |
| 2–4 | Heading | Section headings always start in column 2 |
| 2 | Text | The main paragraph |
| 3 | Text 2 | A second paragraph, list or detail |
| 4 | Action | Buttons and links, asides, small images |

Images only span ¼, ½, ¾ or the full width, in portrait 4:5, landscape 3:2 or wide 16:9. Rows are
top-aligned and separated by fixed spacing steps (`--s1`–`--s5` in the stylesheet); nothing uses
one-off margins. In the templates (`src/pages.mjs`), `sectionHead()` builds the label and heading row,
and `row([{ col, span, html }])` places content in the slots. In a preview build, press **G** to overlay
the grid and check alignment.

**Type.** Three faces, paired as in the Tanker × Space Grotesk reference:
- **Tanker** (Indian Type Foundry, via Fontshare, ITF Free Font License): uppercase display headings.
- **Space Grotesk**: body copy and statements. In display headings, an accent word is set in
  Space Grotesk Light.
- **Space Mono** (typewriter): labels, index numbers, captions, navigation and buttons.

Space Grotesk and Space Mono are open-licence (SIL OFL) and self-hosted in `src/assets/fonts/`.
Tanker isn't redistributed in this repository. By default the site loads it from Fontshare.
To self-host it instead, download Tanker from fontshare.com, save the WOFF2 as
`src/assets/fonts/tanker.woff2` and rebuild; the build detects the file and stops using Fontshare.
Until Tanker loads (or if it can't), headings fall back to self-hosted compressed Archivo.
A small script refits headlines after fonts load, so no line overflows the grid, and makes the
footer wordmark fill the full width.

In `content/site.mjs`, wrap a word in asterisks to set it as the accent, for example
`'Movement.', 'Recovery.', '*Connection.*'`. In statements, the accent word turns grey.

**Colour and atmosphere.** Dark and cinematic: near-black backgrounds, off-white text, photography
shown in black and white (colour returns on hover where an image is a link), a fine film grain, and
one accent, DISTRIK red (`--accent`). Change `--accent` to restyle every accent at once.

**Intro loader.** On the first page view of each visit, a 1-second loading screen plays (crosshair,
typewriter text, red progress line). It is skipped for visitors who turn off motion, and the page
works normally without JavaScript.

**Menu and footer.** The Menu button opens a sitemap panel with two image tiles (DISTRIK and
Corporate Wellness); the footer repeats the same sitemap rows and tiles.

Colours, spacing and type sizes are defined at the top of `src/assets/styles.css`.

## 4. Connecting the enquiry form

The corporate enquiry form ships in **preview mode**. It validates input but sends nothing, and tells the
visitor so. It never shows a success message unless a real service confirms delivery.

To connect it to any service that accepts a standard form POST and returns 2xx (Formspree, Basin,
Getform and similar):

1. Create a form with the provider, set the destination inbox, and copy the endpoint URL.
2. In `content/site.mjs`, set `forms.corporate.endpoint: 'https://formspree.io/f/xxxxxxx'`.
3. Rebuild. The preview notice disappears, submissions post to the endpoint, and visitors see
   "sent" only when the service returns success.
4. Send a test enquiry and confirm it arrives.

Submitted fields: `name`, `email`, `company`, `location`, `looking_for`, `message`, plus a hidden `_gotcha`
honeypot for spam (Formspree recognises this name).

DISTRIK enquiries go directly to hello@distrikath.com, Instagram and Fresha. No form is needed.

## 5. Preparing the domain for launch

1. **Own repository.** Copy `thesavagegroup/` into a new repository, such as `the-savage-group-website`.
   Don't merge this branch into the DISTRIK repo's `main`: that repo publishes `distrikath.com`.
2. **Host.** Connect the repository to a static host (Netlify, Cloudflare Pages or Vercel) with
   build command `npm run build` and output directory `dist`. Before connecting, either commit
   `assets/img/` (already generated) or add `npm run images` to the build.
3. **Final content pass.** Replace placeholders, confirm the review notes, add legal details, connect the form,
   then set `site.preview = false` and rebuild. This removes `noindex`, publishes a normal `robots.txt`
   and sitemap, and hides review notes.
4. **DNS** (at your domain registrar):
   - `www.thesavagegroup.org` → `CNAME` to the host's target (for example `your-site.netlify.app`).
   - `thesavagegroup.org` (apex) → the host's A/ALIAS records, set to redirect to `www`. The canonical URLs
     in the build use `https://www.thesavagegroup.org`.
   - Turn on HTTPS in the host and wait for the certificate.
5. **After launch.** Check every page on a phone, submit a test enquiry, submit `sitemap.xml` in
   Google Search Console, and set up a 404 rule if the host needs one (`dist/404.html` exists).

## Checks performed for this build

- Desktop (1440px) and mobile (390px) screenshots of every page, including image crops on phones.
- Mobile menu: keyboard open/close, Esc to close, focus moves into the menu and back, `aria-expanded`.
- One `h1` per page with no skipped heading levels, and unique titles and meta descriptions.
- All internal links and anchors resolve, and all images load.
- Text contrast (WCAG AA): body 16:1, muted text 6.4:1, muted text on dark 8.1:1.
- Grid overlay check: images, headings and text align to the quarter columns.
- Form: required-field validation, no network request and an honest "not sent" message while unconnected.
- `prefers-reduced-motion` disables transitions and smooth scrolling. Images below the fold use `loading="lazy"`,
  and every image has width and height set.
